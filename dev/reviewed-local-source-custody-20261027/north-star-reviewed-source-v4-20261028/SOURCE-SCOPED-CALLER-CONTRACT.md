# Offline source-scoped product context caller

`candidate/scripts/source_scoped_north_star_consumer.py` provides an actual value-returning local reader, not an application endpoint or a count-only query. Its roots must be the authorized immutable bulk source, completed structural sidecars and completed basis-restoration output. Callers supply the two exact final derived-manifest pins; both must bind the same source manifest.

The lookup key is `(source ID, source release, literal identifier namespace, literal identifier value)`. Leading zeros and namespaces are not normalized. A source identifier labelled GTIN is not thereby granted a validated canonical GTIN or a cross-source identity. Duplicate source keys return an ambiguous result rather than selecting a product. Missing keys return a typed not-found result without an external fallback.

Candidate output requires `include_candidates=True` exactly; truthy strings or integers do not opt in. The reader checks the pinned read-only indices, exact source asset/packet location, the selected producer's one-resource/one-citation contract, every fact/edge citation reference, public scope, source/release, identifier assertion digest and explicit product→profile edge digest. It returns the verified citation objects, including original licence and attribution, alongside product and profile resources. Derived nutrient context and per-nutrient basis candidates must match the exact input packet digest and source selection.

The response distinguishes original source resource/identifier/edge evidence from additive nutrient and basis candidates. Unknown quantities and source-specific states remain unchanged; original quantity values, source definition and method remain available inside the candidate context. It always reports zero accepted identity joins and false nutrition-aggregation, automatic-planning and application-activation eligibility. It does not silently compose recipe totals.

The fixture tests exercise the real retained original packet producer, both full sidecar producers and their SQLite indices. They cover returned values and restored state, citation provenance, candidate opt-in, namespace/leading-zero/release distinctions, ambiguity, digest tampering, merged-source refusal and unchanged input indices. This synthetic integration proof is separate from actual corpus query coverage. The latter must be exercised after the complete basis locator and both final manifests exist; no such production caller result is claimed by this document.

The caller reads only already-approved worker-local inputs. Full responses stay on that worker; any diagnostic exported from an actual exercise must contain aggregate results and pins rather than record contents. No external food lookup, new acquisition, source-rights upgrade, app wiring or Cloudflare activation is performed.
