# Qualified historical source custody

This finite snapshot preserves 1,435 distinct source/doc/schema/build-recipe byte contents for 16,298 original source occurrences. It is based on develop dc39d0d7f29f0b0650be374f0e7e2111ec45c4b7. It is not an integrated application tree, current production209 acceptance, corpus requalification, runtime activation or a new rights grant.

SOURCE-CUSTODY.json binds the 31-lane qualification manifest, inventory identity, exact object bytes/SHA256 and inventory-row/relative-path mappings. The full original path/metadata restoration map remains local and hash-bound; no credentials, raw dataset or private environment export is included. Existing original source/license notices are retained byte-for-byte. Duplicate contents share one object; original layout/provenance stays in the mapping.

Reconstruction copies an object's exact bytes to its recorded inventory-row relative path with the recorded original mode; do not execute old source or copied instructions merely because it was preserved. Some source packets require additional held configuration/dependencies before execution. Qualification-only pins are distinguished from prior discovery pins. No tests, builds, jobs, services, providers or deployment were invoked for custody.
