## Actual boundary and contract

`cloud/pack-cost-owner23.mjs` exports `createPackCostBasketRoutes`. Its returned function handles only POST `/api/catalogue/pack-cost`, returning null for unrelated paths. It checks same origin, owner-supplied authentication, configured independent helper approval and bounded body before reading private source records. It uses the existing `catalogueRows` metric reader and `calculateBasket` consumer; nutrient calculation is not reimplemented.

Body: `{basket, date, currency, selections, budgetMinor?, maxStoreStops?}`. Basket has 1–100 unique lines. Each optional selection is `{lineId, product:{id,sha256,updatedAt}, price:{id,sha256,updatedAt}}`. Reference digests are the SHA-256 of exact stored UTF-8 JSON bytes. Source rows are fetched from `unified_records WHERE owner=?`, with the authenticated account, never a supplied owner. Only existing uncompressed product/priceObservation rows up to 200000 characters are supported; compressed records are withheld. The two source records must have exactly one identical 8–14 digit barcode string. Leading zeros are retained. Names and dietary equivalence are not used as identity evidence.

Both sources must retain licence/rights metadata and not be withdrawn/quarantined or past explicit retention/access dates. The server `reviewBinding` hook receives clones of the exact record snapshots, line, full line digest, account, date, currency and injected clock. It must return a currently accepted, authoritative receipt bound to account, full line digest/id/quantity/unit, source IDs and both source digests. It must explicitly establish as-sold quantity basis, exact full-pack price, inclusive tax, satisfied price/promotion/loyalty/store conditions and permitted derived reuse. A static `allowed:true`, source allowlist or request checkbox is insufficient. This implementation validates the returned fields, but does not produce those qualification decisions itself. Owners 02/07 must connect their independently reviewed authoritative rights/binding provider; a server hook that simply reflects the request is outside this contract.

Source price date/currency, validity window and product pack value/unit come from the stored record, not the request's offer/fee claims. Missing pack never defaults to one package. Edible grams and prepared quantities do not become as-sold pack needs: line state and receipt basis must explicitly be as-sold. Price amounts must fit the trusted currency minor-unit definition exactly; sub-minor precision is withheld, rather than rounded. The retained helper checks date/unit/currency compatibility, rounds pack count, distinguishes purchase from consumed cost, and evaluates explicit budget/store-stop bounds.

Fees come only from server-reviewed evidence: complete store fee, account/date/currency, evidence ID and integer amount. Missing fees withhold complete totals. Conflicting store fee amounts reject the calculation. The response retains fee evidence IDs/review IDs/source price digests. Prices, packs, source identifiers, source snapshot hashes/dates, review IDs and private uncertainty survive into the result. Each bound source is read and checked again after asynchronous review, producing 409 if changed. This is a read-only snapshot estimate, not a transaction authorizing later purchases; source/policy changes after the snapshot require recalculation.

Output: `{composition, costs, sourceSnapshotAt, scope:'private account', persisted:false}`. Costs include per-line bindings and explicit `{totalLines, pricedLines, unknownLineIds, ratio}` coverage. Count coverage is not quantity coverage or affordability. Known subtotal is partial; unknown entries stay present and complete budget is withheld. Availability stays unknown, regardless of same-day price. No safety, allergy, nutrition equivalence, expiry, ownership or purchase authority is inferred.
