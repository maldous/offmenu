## Implemented file boundary

public/calendar-roundtrip-owner31.mjs offers importCalendarFile(File,
{confirmed:true}) and exportCalendarFile(view,{confirmed:true}). Import reads
only a user-selected .ics Blob/File, streams at most 256 KiB, unfolds at the byte
level before fatal UTF-8 decoding and records original filename/size/SHA256.
It requires one complete VCALENDAR, VERSION 2.0, PRODID and UID/DTSTAMP on each
of at most 100 top-level events; component nesting and line count are bounded.
Invitation methods other than PUBLISH reject. It fetches no ATTACH/URL/TZURL,
does not expand recurrences, schedule alarms, send invites or contact providers.

The file representation preserves original unfolded values/parameters/order,
UID, quoted parameters, VTIMEZONE STANDARD/DAYLIGHT rules, civil/floating/UTC
values, all-day values, RRULE/RDATE/EXDATE and RECURRENCE-ID exceptions. Output
uses CRLF and Unicode-safe folding at 75 UTF-8 octets. Source X-provenance and
unknown fields roundtrip when explicitly included. This is semantic content-line
preservation, not byte identity (fold placement changes); original file digest
and exported file digest can differ. File selection is not source admission.

RFC reference: https://www.rfc-editor.org/rfc/rfc5545.html, especially 3.1
(content lines), 3.3.5 (date-time), 3.6.5 (timezones), 3.8.5 (recurrence).
The reader is a bounded structural importer, NOT a full RFC semantic validator,
timezone database or recurrence evaluator. Invalid calendar dates/recurrence
semantics may remain opaque with warnings. Missing TZ definitions, floating
ambiguity, DST gaps/folds, measurement bases and quantities stay unresolved;
no host timezone, medical safety, nutrition equivalence or country inference.

Default export conservatively removes private text, attendee/organizer/member
fields, unknown properties/parameters and alarms; reports removed field names.
Temporal/identity properties remain identifying information: this is not an
anonymization guarantee. To roundtrip private/unknown source fields, callers
must explicitly request includePrivate:true AND privateConfirmed:true in addition
to export confirmation. If redaction removes required UID/DTSTAMP, export fails
rather than invent identities. Source provenance is retained in local export
receipt even when its X-property is redacted from the shared file. Editing view
properties does not edit the internal imported source or forge its provenance.
No DOM rendering exists; owner UI must use textContent for untrusted fields.
