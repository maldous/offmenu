## API and trust boundary

`public/private-aggregate-admission-owner59.js` exports:

```js
const validator = createPrivateAggregateValidator({
  authority, getContext, clock, mode: 'authoritative',
});
const decision = await validator.assess({selectionId});
```

There is no default authority and default mode is unqualified. The caller supplies only an opaque selection ID. It cannot supply receipts, audience, permissions, actor context or policy decisions. `getContext()` is trusted authenticated context with exactly accountId, actorId, sessionEpoch, purposeId, market and audience=`private`. Actor-to-account permission must be established by the owner adapter, not inferred from these names. A changed account, actor, session, purpose or market during evaluation denies. The clock must be a trusted nonnegative nondecreasing integer.

This library **does not authenticate an injected authority or authenticate reviewer IDs**. Strings such as `independently-qualified`, hashes or `approved` are not proof by themselves. A browser/request object or stored replay of producer claims must never be used as the authority. Only an independently qualified owner-controlled store may supply these capabilities. No such store or real eight-receipt set is supplied here; actual admission remains unqualified.

### Mandatory store capabilities

- `authority.read({selectionId, context})` returns `{selection:{id,revision,document}, receipts:[{id,revision,document}, ...]}` from trusted store rows.
- `authority.readIfCurrent(expected, consume)` must conditionally read the exact current selection and **independently authoritative** receipt, source, rights, contribution, withdrawal, release-history and privacy-budget state together. It invokes `consume(rows)` synchronously exactly once if current, then returns `{matched:true}`; otherwise it refuses. It must not certify a cached snapshot or client-claimed epoch as current. Selection/receipt revisions must advance for any change, including ABA restoration.

The validator snapshots before hashing, binds exact row/revision/document bytes and each receipt SHA-256, then rechecks the complete snapshot and authenticated context inside the conditional callback. After its await, context, nondecreasing time and the earliest admitted deadline are checked again. Missing/repeated callbacks, stale rows, expiry at equality, async pseudo-grants, store errors and invalid metadata deny with a fixed non-sensitive reason. No raw document, account context or adapter error is returned on denial.

The current gate establishes a decision at its conditional read point. **It is not a future-use lease or a distributed transaction with a later data operation.** This validator performs no data operation. The application/store owner must couple an actual read/write/use to a fresh conditional gate and qualify withdrawal races for that operation. A revocation after the linearization point is not retroactively prevented by this helper; every later operation needs a new gate. No cross-region/D1 parity is claimed.

## Exact evidence contract

Selection format is `owner59-private-aggregate-selection/1`. It binds ID/revision, private scope, validity interval, exact query/output/contribution-snapshot/history SHA-256 values, input-pin-graph SHA-256, producer commit/path/implementation digest/epoch, and eight distinct receipt pins (kind, ID, revision, exact document SHA-256). The canonical input graph digest is recomputed; the output digest is an authoritative producer attestation, not a payload hashed by this validator. No payload is accepted or released.

Every receipt uses `owner59-private-aggregate-receipt/1`, the exact selection ID/revision/scope/bindings, explicit approved decision, reviewer ID, assessment digest, evidence class and bounded validity interval. Selection/receipt JSON documents are each bounded to 64 KiB. Unknown, absent, expired or unreviewed evidence denies. Additional metadata cannot replace required gates. The test fixture shows the exact serialized structure, with fabricated values clearly labelled synthetic.

| Receipt | Required evidence and enforced checks |
| --- | --- |
| producer | Explicit independent qualification and exact producer commit/path/digest/epoch matching the selection; no missing producer acceptance inferred. |
| lineage | Complete explicit graph of 1–128 unique input IDs, source IDs/revisions/content hashes, dependency IDs and explicit independent-root status. Missing dependencies, cycles, implicit roots and duplicate IDs deny. Current validity, freshness and retention clocks are separate and mandatory. Graph digest must match the selection. |
| rights | Exact one-per-input current revision/hash, active permission epoch, same private aggregate purpose/action/audience and validity. Public/transient/display permission is insufficient. |
| contribution | Same exact per-input coverage with a separate current purpose/choice decision. This narrow contract conservatively requires a reviewed contribution receipt for every input; no not-applicable or public-fact shortcut is invented. Unsupported cases need an independently reviewed schema revision. |
| cohort | Reviewed unit (person/household), minimum observed/required distinct units, maximum contribution bound and observed contribution, exact rule-set digest, plus small-cell, complement and rare-attribute decisions. Minimum>=2 is only a conservative structural bound, never an anonymity threshold. Test values 5/6 are synthetic, not approved parameters. Counts are authoritative attestations, not recomputed from people by this helper. |
| composition | Current ledger ID/revision and explicit intersection, differencing, temporal, linkability and release-closure review. Exact history digest is in the common binding. No adaptive-query safety is inferred from an ordinary provider quota. |
| privacyBudget | Current reserved disclosure-composition receipt, exact ledger ID/revision matching composition, reservation ID, reviewed mechanism/parameters and charge-receipt hashes. Provider request budgets, unknown mechanisms, missing reservations and exhausted status deny. No epsilon/delta or differential privacy guarantee is invented. |
| revocation | Current withdrawal epoch, all inputs/dependencies current, no pending withdrawal, and restore replay current. The trusted store must bind these claims to independently current rows; a boolean in untrusted JSON is not authority. |

Rights/contribution intervals and all input validity/freshness/retention deadlines participate in the earliest decision expiry. The helper does not charge/consume a reservation. That reservation must already be durably committed for this exact output/query/history and coupled to future use by its owning caller; it cannot be recycled for a different selection or output. Repeated reads and randomized output composition still require the actual reviewed ledger policy.
