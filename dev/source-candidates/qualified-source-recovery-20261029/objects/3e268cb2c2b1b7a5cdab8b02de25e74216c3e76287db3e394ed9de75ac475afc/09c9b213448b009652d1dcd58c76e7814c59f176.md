# Bounded common-package transport

`public/common-corpus-transport.js` exports `loadCommonCorpusPackage(options)`.
It verifies an explicit slice of an existing `offmenu-common-package/1` release,
merges the selected `offmenu-common/1` packets, and returns `{corpus, receipt}`.
`corpus` is the unchanged `createCommonCorpus` adapter. This is ready for Morgan
review; app wiring and release admission remain separate owned work.

```js
import {loadCommonCorpusPackage} from './common-corpus-transport.js';

const {corpus, receipt} = await loadCommonCorpusPackage({
  manifestUrl: 'https://approved.example/common-data/manifest.json',
  manifestSha256: reviewedExactManifestByteHash,
  acceptedReleases: [{
    releaseId: reviewedReleaseId,
    manifestSha256: reviewedExactManifestByteHash,
  }],
  files: [{
    key: 'recipes/part-0000.jsonl.gz',
    sha256: reviewedExactGzipByteHash,
    packetIndexes: [0, 12],
  }],
  allowedOrigins: ['https://approved.example'],
  fetchImpl: (url, init) => fetch(url, init),
  limits: {files: 1, packets: 500}, // may only lower hard ceilings
  readerOptions: {userId: null, allowLocalRestricted: false},
  signal: abortController.signal,
});
const name = corpus.resolveField(knownResourceId, 'name', 'en');
```

The placeholder pins must come from owner-qualified, independently reviewed
release evidence. Never fetch a manifest and automatically accept its own hash
or release ID. The embedded legacy `manifestSha256` is a producer payload digest,
not a file-byte digest; it is deliberately unused here. The package contract is
`offmenu-common-contract/1`; the graph schema is `offmenu-common/1`. The supported
producer status is `all-packets-schema-identity-citation-and-scope-checked`.
A matching status alone does not admit a release: its ID and exact manifest byte
hash must match the caller's explicit accepted-release pair. No release is built
into the transport as globally accepted.

Selection and integrity:

- Every selected gzip file needs its own explicit SHA-256 pin, matching the
  exact-byte-pinned manifest. Size and packet count come from that manifest.
- Only explicit `concepts`, `recipes`, `terminology`, or `ontology` partition
  keys are fetched. Missing metadata or an out-of-range packet index rejects
  before file fetch. `packetIndexes` is a nonempty array of distinct zero-based
  indexes; omitting it selects the whole file. Selection follows source file
  order, irrespective of index-array order.
- The complete selected compressed file is size/hash checked before gzip
  decompression. Every packet in that file is framed, parsed and structurally
  checked, including packets outside the selected indexes. These costs count
  against the budget; gzip does not provide random access to packet indexes.
- Exact duplicate rows across packets deduplicate by category and ID, comparing
  JSON object keys without ordering significance. Conflicting rows reject.
  Duplicate IDs inside one packet reject. No IDs, strings or Unicode are changed.
- Packet-local citations must close. Resource joins may remain unresolved;
  they are retained and never trigger fetches or inferred reconciliation.
  The adapter continues to control scope filtering, source-text fingerprints,
  translation eligibility/conflicts and source fallback. Invalid nested scopes
  on text/translation objects reject because that schema does not support them.
- Consumer structural checks cover graph shapes, known row/value fields, typed
  values, scopes, citation references and basic absolute IRI syntax. They do not
  replace the producer's full schema/semantic, licence or release qualification.
  The adapter verifies source-text digests for accessible selected text; it does
  not qualify unselected source text or independently prove translations correct.

Network and runtime constraints:

- Fetch is an explicit trusted injected capability. All URLs use canonical HTTPS
  allowlisted origins, safe ASCII package paths and no credentials/query/fragment.
  Encoded path components, traversal, backslashes and URL-like keys reject.
- Requests use GET, `redirect: 'error'`, `credentials: 'omit'`,
  `referrerPolicy: 'no-referrer'`, and `cache: 'no-store'`. A non-200 response,
  redirected response or changed final URL rejects. Synthetic/local injected
  responses may have an empty URL; real Fetch responses carry their final URL.
  An injector must honor redirect/abort options and must not perform hidden I/O.
- HTTP `Content-Encoding` must be absent or `identity`: the response body must
  contain the pinned gzip file bytes, not an HTTP-decoded variant. Network/CDN
  configuration and CORS must support this contract; this change does not alter them.
- Requires native Fetch-compatible byte streams, Blob, `DecompressionStream`,
  fatal UTF-8 `TextDecoder`, and Web Crypto in a secure context. Tests and probes
  ran on Node 24; live browser/network qualification remains an integration gate.
- Invalid gzip (including bad CRC/truncation), invalid UTF-8, invalid JSON, empty
  lines, unsupported packets and conflicting identities reject atomically.
  No partial corpus is returned. A final JSONL newline is optional.

Hard ceilings per call (all overrides must be positive safe integers at or below
these ceilings):

| Limit | Ceiling |
| --- | ---: |
| Manifest bytes / file entries | 1 MiB / 4,096 |
| Explicit selected files | 2 |
| Compressed bytes per file / total | 8 MiB / 8 MiB |
| Decompressed bytes per file / total | 32 MiB / 32 MiB |
| Packet bytes / packets read | 2 MiB / 1,000 |
| Rows / JSON nodes visited | 50,000 / 500,000 |
| JSON nesting depth | 64 |
| Stream reads, including EOF and empty chunks | 16,384 |
| Async I/O deadline | 30 seconds |

Rows/nodes/packets count all inspected packets, not only the returned selection.
Byte and read limits include actual streamed data and cancel on overrun. The
manifest has a separate byte budget; compressed/decompressed counters are
cumulative across the complete selected batch. Timeout/abort interrupts fetches,
body reads, decompression reads and awaited hashes; synchronous JSON work can
only yield at bounded packet boundaries. This is a byte/work budget, not an exact
JavaScript heap cap: decoded buffers, indexes, row comparison strings and the
adapter's immutable clone also consume memory.

There is no search endpoint, next-page cursor, dependency chasing or corpus scan.
Selecting one packet still reads its entire partition. A partition exceeding the
limits rejects; do not hide it behind a loop over partitions. Reviewed composition
must enforce an aggregate budget if it intentionally invokes multiple calls.
Producer-owned smaller delivery partitions or an independently bounded index may
be needed for larger recipe files; this transport does not invent those formats.

Verification (no server, installs, external writes or corpus copies):

```sh
node --test tests-web/common-corpus-transport.test.mjs tests-web/common-corpus-i18n.test.mjs
node scripts/probe-common-corpus-transport.mjs --synthetic
node scripts/probe-common-corpus-transport.mjs docs/common-corpus-transport-reference-plan-20261014.json
```

The standalone probe accepts one JSON plan up to 64 KiB. Plans require an explicit
local package root, exact manifest pin, accepted-release pairs and file pins.
It uses a synthetic HTTPS namespace with an injected local reader, rejects
symlinks escaping the package root and makes no network requests. Caller-reviewed
local acceptance in a probe does not confer production release acceptance.

Committed synthetic and reference receipts record hashes, limits, reads, counts,
wall/CPU time and RSS samples. Times are observations, not performance guarantees.
`processMaxRssKiB` may include an inherited launcher high-water value; the RSS
samples are not a peak heap measurement. The reference plan uses the externally
retained reviewed package root without copying data. It reads only the 32,624-byte
manifest and `concepts/part-0000.jsonl.gz` (108,265 compressed / 726,339 decompressed
bytes, 500 packets); only indexes 0, 249 and 499 reach the adapter. This proves one
bounded slice, not qualification of all 170 manifest entries or all source data.
