## Supported workflow

Use `python3 -B scripts/offmenu-gitflow.py --repo WORKER_PATH --policy POLICY
--evidence-dir RECEIPTS COMMAND ...` on Linux with Python 3.10 or newer and Git.
There are no package installs or external Python dependencies. Child Git commands
and synthetic test helpers remove **all inherited `GIT_*` variables**, including
repository paths, object/namespace overrides and config injection, from child
environments. They explicitly restore only optional-lock and noninteractive-prompt
settings so the explicit repository path
controls custody. Parent environment variables and permission controls stay intact. POLICY and the
canonical RECEIPTS directory are retained outside the worker checkout. Each
attempt writes an exclusive JSON receipt, including blocked attempts. A local
advisory lock serializes managed operations in that directory. Keep one canonical
receipt directory; changing/deleting it defeats custody and is not supported.

`--check-only` runs real fetch/validation and writes evidence but does not create,
switch, merge, tag or delete a branch. A zero exit means `allowed` for a check or
`completed` for execution. A blocked gate exits 2. JSON stdout gives the exact
receipt path and error. Git commands time out at 45 seconds, use no terminal
credential prompt, and do not retry using a cached base. A timeout records exit
as unavailable, never success. Successful fetch records the actual exit code,
UTC times, exact command and full SHA of the explicitly fetched canonical
tracking ref under `/tmp/offmenu-develop-fetch.lock`. Fetch uses
`--no-write-fetch-head` and does not depend on shared FETCH_HEAD. A busy shared
lock fails closed without cached fallback. Disposable local bare fixture origins
use their own per-origin lock and do not contend with the live native pool. Branch names/HEAD remain unchanged on validation failure.
Fetch itself can write objects/tracking refs/FETCH_HEAD; it is not a read-only
network probe.
