# OffMenu Impeccable guidance

This is a project-local, documentation-only adaptation of selected Impeccable references. It supplements existing frontend-design skills and Emil Kowalski guidance. It does not replace them or install the upstream engine.

## Scope and design authority

- Respect any current UI pause. Installing or loading this guidance does not resume UI implementation or change dataset priorities. Check the latest task direction before editing.
- The user's approved OffMenu brief, existing branding, tokens, typography, assets, components, and accepted design decisions govern the result. Read existing project context directly; do not overwrite context files, frontend skills, or identity with Impeccable defaults.
- Keep the existing application framework. Do not introduce React or Preact, their adapters, JSX-based replacements, or dependencies that require them.
- Preserve the requested full-viewport experience, Emil Kowalski-inspired interaction quality, and elegant line-based 3D direction. Generic reference preferences do not cancel those requirements.
- Keep work inside the requested surface and purpose. Refinement preserves identity, behavior, factual copy, and everything outside scope. Existing user approvals remain applicable; ask only for material unresolved decisions or mandatory platform confirmations.

## Runtime boundary

This package contains documentation and provenance only. It has no executable helpers, engine, hooks, browser overlay, local server, updater, telemetry, or credential configuration.

Do not obtain or run Impeccable scripts, npx installers, hooks, detectors, live mode, direction catalogs, image-generation routes, or repair commands as a consequence of loading these references. Do not change CSP, security trust, package manifests, or external-service setup for this guidance package. Any optional runtime addition is a separate installation task, with its own source review and required permissions.

Use the project's existing approved tools for rendering and checks. Source snippets in the references illustrate implementation ideas for a separately authorized UI task; they do not authorize dependency installation or external transmission. An unavailable check must be reported as unverified.

## Use the smallest relevant reference

Read the target, its existing styles/components, and relevant project context first. Pick the surface mode: Operate for task UI, Read for documentation, Persuade for a landing page, Experience for a showcase. Modes describe the visitor's task; they do not impose a new look.

- UI quality report: [audit](references/audit.md)
- Product UI conventions: [operate](references/operate.md)
- Final scoped refinement: [polish](references/polish.md)
- Layout/full-viewport adaptation: [layout](references/layout.md), [adapt](references/adapt.md)
- Typography and palette: [typeset](references/typeset.md), [colorize](references/colorize.md)
- Interaction and motion: [animate](references/animate.md), [delight](references/delight.md)
- Resilience and measured performance: [harden](references/harden.md), [optimize](references/optimize.md)
- Scoped intensity or simplification: [bolder](references/bolder.md), [quieter](references/quieter.md), [distill](references/distill.md)

Before an authorized UI edit, consult [craft floor](references/craft-floor.md) as a quality checklist, subject to the approved brief. Preserve intentional exceptions instead of redesigning them to satisfy generic rules.

Verify the actual changed behavior and rendered result at relevant viewports, including reduced motion and keyboard access. Report the files changed, checks actually run, remaining limitations, and any decision needed. Do not claim that this package ran an Impeccable detector or that documentation installation changed the UI.
