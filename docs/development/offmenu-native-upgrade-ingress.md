# OffMenu native replacement ingress

This source entry applies only to `maldous/offmenu`,
`offmenu-stokowski-current.service` and the canonical native harness replacement
targets, including `/opt/offmenu-publisher`. It consumes one signed owner
confirmation for a combined staging and stopped-host replacement. It does
not start the unit or publish an issue.

## Protected enrollment and release

The Foo host owner must independently verify an already authorized OffMenu
installer principal against the real non-root Foo Unix account and confirm
the fingerprint of that principal's existing public signing key for this
specific purpose. No inherited UIF signer, wildcard, key creation, or
agent-issued enrollment is used. The host owner prepares one OpenSSH
allowed-signers line with the exact Unix principal, key type and public key.
Verify the public fingerprint with `/usr/bin/ssh-keygen -lf <existing-public-key>`
in the owner's trusted environment. The owner's approved, protected host
administration interface performs the create-only enrollment. On a newly
prepared root-controlled directory, the file operation is:

```sh
test ! -e /etc/offmenu-native-upgrade/allowed_signers &&
test ! -L /etc/offmenu-native-upgrade/allowed_signers &&
/usr/bin/install -o root -g root -m 0644 "$owner_verified_allowed_signers" \
    /etc/offmenu-native-upgrade/allowed_signers
```

The root owner independently approves and provisions the reviewed executable
closure at `/usr/local/lib/offmenu-native-upgrade-v2`. Preserve `tools/delivery/`
for the ingress, canonical native harness package, upgrade, adoption and
contract modules and their protected owner/publisher install dependencies.
Include `contracts/schemas/delivery-handoff-v1.schema.json` and independently
qualified locked `jsonschema`, `packaging` and transitive runtime files under
`deps/`. The tree contains only fixed release code and its dependencies.
Keep every ancestor, directory and regular file root-owned and free of
group/other writes. Symlinks and hardlinked files refuse. Install the reviewed
exact bytes using the existing host release procedure. The candidate package
and all request data are outside the executable tree.

The previous immutable shelf remains at
`/usr/local/lib/offmenu-native-upgrade`. Preserve its bytes and receipts.
Deploy the reviewed v2 closure at the fixed sibling path; do not rename,
overwrite or alias either shelf. The versioned basename is not derived from
a digest. Build the closure with that literal path first, then independently
qualify its whole-tree digest and bind the existing private loader to that
exact shelf before importing any module from it. The signed namespace and
protected original-operation state are unchanged.

The protected release identity is computed over the exact file names and
SHA-256 values. From the authenticated Foo owner transport, use:

```sh
/usr/bin/python3.12 -I -S -B \
    /usr/local/lib/offmenu-native-upgrade-v2/tools/delivery/offmenu_native_upgrade_ingress.py release-id
```

## Owner request and original operation

The owner provisions the root-controlled directory
`/var/lib/offmenu-publisher/upgrade-ingress/publisher-fence/` beside the
operation packets. Keep it and its append-only intent files with the
protected receipts. A missing or unreadable fence refuses replacement.

For one owner-selected lowercase 64-hex operation ID, use the protected
directory `/var/lib/offmenu-publisher/upgrade-ingress/<operation-id>/`. Its
root-controlled packet contains:

- `package/`, the immutable independently reviewed package generated by
  the non-root package owner through `prepare_coherent_package`. Its
  manifest binds a typed `PackageAcceptance` from the actual package owner.
- `package-review.json`, the exact protected acceptance input referenced
  by the package manifest as path `package-review.json`. Its schema
  `offmenu.native-package-review/1` contains exactly `schema`, `owner`,
  `head`, `tree`, `author`, `reviewer`, and `verdict`. The actual independent
  verdict must be `accept` and bound to the exact source and owner. The host
  owner verifies that provenance before signing. Caller assertions alone
  do not establish independent review.
- `preflight.json`, the actual accepted adoption plan from
  `native_harness_adoption.prepare`, with independently accepted component and
  coherent validation evidence, current stopped witness, and original effects resolved.
- `upgrade.json`, the exact canonical upgrade object. Its original operation
  matches the directory and its new role closures match the package. The existing
  prior closure, rollback slots and original legacy receipt pins remain required.
- `custody.json`, the exact independently qualified object with fields
  `quiescence`, `locks`, `publisher`, and `public_ca_pins`. Supply the
  canonical dataclass fields for `Quiescence`, `LockCustody`, and
  `PublisherConfigCustody`. Supply canonical `PublicCARecordPin` entries
  when required, or JSON null. Tuples are encoded as JSON arrays.
  Existing custodians supply the native quiescence and three lock records,
  and only qualified publisher directory/key metadata. Do not supply key bytes.

The verified enrolled owner confirms the exact request with a detached
OpenSSH signature. The `request.json` has exactly these fields:

| Field | Value |
| --- | --- |
| `schema`, `action` | `offmenu.foo-native-upgrade/1`, `replace` |
| `repository`, `unit`, `target` | `maldous/offmenu`, `offmenu-stokowski-current.service`, `/opt/offmenu-publisher` |
| `owner`, `operation_id` | Enrolled Unix principal and original directory ID |
| `package_sha256`, `release_sha256` | Exact package manifest digest and installed release ID |
| `inputs` | Map of the four fixed JSON input filenames above to their exact byte digests |
| `issued_at`, `expires_at` | Integer UTC epoch seconds, validity at most 300 seconds |

Serialize the request as ASCII JSON with sorted keys and compact separators
and terminate it with one newline. After reviewing all pins and fresh actual
host confirmation, the owner signs in their own environment with the existing
key. Only the request and detached signature enter host custody.

```sh
/usr/bin/ssh-keygen -Y sign -f "$existing_owner_key" \
    -n offmenu-foo-native-upgrade-v1 request.json
```

Use the original operation ID with one protected invocation:

```sh
/usr/bin/python3.12 -I -S -B \
    /usr/local/lib/offmenu-native-upgrade-v2/tools/delivery/offmenu_native_upgrade_ingress.py \
    replace "$operation_id"
```

The ingress rechecks authenticated pins and stopped service under the
existing custody locks before the first effect. It retains those same locks
while calling the canonical materialize and upgrade code. Before staging,
the fixed publisher fence is checked against all operation receipts under
those locks. A publisher intent is durable before the per-operation intent
or any staging. Every new operation refuses while a retained original is
unresolved, or when the fence, packet, or receipt evidence contradicts it.
A completion binds the exact retained canonical installed receipt. All
intents and receipts are create-only. The exact signed
request, with the same reviewed release and signer, can be queried with
`status "$operation_id"`, including after its mutation authorization expires.
`reconcile` means the owner must observe the original canonical operation.
Preserve all receipts and partial slots. A second confirmation or invocation
must not be used to replace an unresolved original. `installed` is the
canonical stopped-host installation result. Service start and the private
issue publication invocation are separate owner actions.

## Foo job self-approval boundary

The Foo job route can be attached here once the existing platform supplies
authenticated current-job provenance. It has no mutation entry in this source.
The existing OpenSSH owner route is unchanged.

The deployed Windmill `u/admin/foo_root_jobs` authenticates its connection to
Foo. Its `foo-root-exec-v1` request currently forwards a caller-selected
`job_id` and shell command, working directory, and timeout. It sends no
server-authenticated Windmill actor or platform run ID to the fixed ingress.
A root UID, environment variable, transient unit name, caller receipt,
or reusable transport access cannot supply those facts.

The missing hook is at the maintained runner's authenticated admission
boundary, before turning the current job into a shell command. It must carry
the immutable platform run ID and initiating principal from the authenticated
invocation through the protected Foo bridge to the fixed OffMenu operation.
The bridge must bind that same executing job to the permitted OffMenu Unix
principal and exact operation, package, source/tree, release, request digest,
and short deadline using existing authorization. Generic commands or supplied
arguments cannot create that attestation. There is no verified deployed hook
on the current protocol and no new signing identity or grant in this change.

The read-only `audit_runner_request` receiver defines the narrow in-process
contract. A qualified adapter must resolve the current authenticated invocation
itself and then return `VerifiedFooRun`. The receiver checks the fixed scope,
protected request and independently accepted package/review pins and reports
the retained original state. The ordinary CLI cannot supply an adapter or
activate this route. A matching audit grants no effects. The eventual fixed
effect boundary still must recheck authenticated provenance, custody and
quiescence under the existing native locks and use the canonical typed
materialize/upgrade methods and durable publisher fence.
