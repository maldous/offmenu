# Fresh post-publication facts under sealed integration admission

The owner may add `integration_admission` outside the immutable publication
snapshot and binding. This keeps the operation, claim, original native source,
validation and accepted review unchanged. The exact seven fields are
`version:1`, `kind:"native-reviewed-integration-v1"`, `binding_sha256`,
`unit_sha256`, `review_sha256`, `permission_sha256` and
`automatic_integration_enabled:true`. It is limited to the existing projected
native integration profile. The review hash identifies the original typed
review file, matching both the projection and `snapshot.review.evidence_source`;
the separate original qualified-packet reference remains unchanged.

The authenticated owner must qualify the genuine source-integration permission
and original review/unit before sealing this record. Its hash-shaped fields
alone grant nothing. The native harness still requalifies its original accepted
unit review and Journal receipt before invoking the fixed publisher.

With this admission, the fixed publisher fetches fresh exact-head/base facts
through the existing GitHub adapter. Any current-head finding, pending review,
changes-requested review or identity mismatch holds integration. The adapter's
bounded response and no-pagination/redirect requirements remain unchanged.
An empty GitHub review list does not become an approval: the original accepted
native review stays the review authority. The fresh Controller observation
retains that review and validation, records the fetched facts and admission hash,
and enables integration only from the sealed permission. The original snapshot
is never rewritten and no future facts hash is invented. The existing intent,
protection, merge preflight, canonical readback and uncertain-effect rules apply.
Without opt-in the prior frozen-facts guard applies; releases are unchanged.

An independent optional `nativeContinuation` carries the same finite data as
`selection.context.publisher_continuation`: exactly `version:1`, `operation_id`,
`unit_sha256`, `packet_sha256`, `claim_sha256`, `previous_selection_sha256`,
`previous_capability`, `previous_record_sha256` and `receipts`. The previous
capability has its original three fields. There are 1–128 unique canonical
invocation UUID receipts, each exactly `{invocation_id,closure_sha256,receipt_sha256}`.
The receipt hash covers the original terminal wire body plus newline. No new
closure is included in this descriptor. The fixed helper independently checks
actual protected claim, old record and original receipts; config shape checks
do not establish that custody. Continuity is not integration permission.
