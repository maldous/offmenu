# Source-only work through the existing native loop

This implements the installed-delivery direction in ADR 0009. Linear owns the
issue, dependencies and acceptance. `develop` remains the integration branch;
release qualification and tagged `main` promotion keep their separate authority.

| Existing facility | Composition and demonstrated missing connection |
| --- | --- |
| Stokowski `Orchestrator._tick`, eligibility, sorting, dispatch, concurrency and retry | `CurrentWork.candidates` observes eligible tracker work. A Root-sealed finite contract or workclass grants qualification; issue text alone grants no execution rights. `owner_policy_refill` runs only inside the fresh native verified-unit boundary. It adds no scheduler or queue. |
| Existing read-only qualification child and Symphony Pool | `owner_policy_contract` checks the original stopped, successful qualification lease and exact source-bound output before deriving a workclass instance. The normal coding admission still checks scope, provider, resources, ownership and dependencies. |
| Git source custody and existing private coding workspace | `stokowski_source` acquires an exact accepted project commit independently of the sealed control revision. Existing per-issue selections remain frozen; unreviewed remote tips do not advance acceptance. It reuses the scoped Git bundle/private clone path and preserves the shared checkout. |
| Original native coding receipt, operation Journal and Windmill dispatcher | `prepare_completed_native` derives the candidate from actual finished coding outputs. The fixed `delivery-unit-focused` profile executes only approved test identifiers from that candidate. It accepts no task-provided shell command. Uncertain jobs reconcile their original identity. |
| Native read-only review and protected publisher/Controller | The generic review template binds the original unit and validation. The fixed publisher preparation entrypoint derives a per-operation configuration under the initial Root policy, retaining normal independent review, exact-head publication and merge readback. Coding children cannot authorize their own merge. |
| Existing Controller checkpoint and publisher custody | The publisher emits an immutable accepted-source fact only from a verified canonical merge and its durable invocation receipt. The fixed reader checks publisher ownership, hashes, selected unit/packet/operation and the chain to the sealed initial seed. Later task acquisition consumes these facts. |
| Native Linear client and current owner state | The opted-in `finalize_source_outcome` callback checks original acceptance, review, validation and canonical source before recording bounded metadata. Full issue closure needs the explicit whole-issue grant. Unknown metadata effects use readback; refill stays withheld until the outcome is verified. |

The dispatch-intent producer creates new evidence exclusively with mode `0600`
before spawning, including under a permissive caller mask. Original intent
bytes and historical flags, operations, leases and receipts remain immutable.
The completed-executor compatibility grant is limited to the exact already
successful original UIF-102 operation and its retained evidence; it cannot
authorize another execution or historical code import.

Root performs one reviewed control/policy installation and dispatcher adoption.
The reusable grant is limited to its listed projects, issue selection, source
paths, resources and synthetic checks. Expired authority, dirty or missing
source, unresolved effects and out-of-class inputs retain a concrete hold.
UIF-102 and UIF-130 cannot acquire whole-parent completion from this source tail.
Application deployment, held-data processing, CIX, USF, Actions, credentials,
spend and release promotion retain their existing holds.

Source tests and independent review qualify a candidate for installation; they
are not evidence that the installed loop ran. Runtime acceptance requires actual
selection, qualification, admission, stopped coding, bound Windmill validation,
independent review, protected integration, canonical source readback, bounded
outcome and a subsequent fresh refill observation, with original identities
retained across recovery.
