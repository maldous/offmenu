# Source category claims

New browser OFF projections retain supplied category and food-group fields, from the reviewed finite source-field list, under `data.sourceCategoryFields`. Original text, codes, hierarchy arrays, language, supplied taxonomy version and unknown keys inside the selected property objects stay unchanged. Category-looking contributor and profile fields are excluded. The product record's existing provenance identifies the source and revision. `provenance.sourceCategoryFields.fields` distinguishes supplied null, supplied values and fields omitted from this input. Omission does not establish absence in the original publisher record. Legacy `data.categories` remains compatible; the claim envelope preserves distinctions that its empty-array fallback loses.

Source categories describe the product. They do not establish ingredient composition, a canonical category or a noningredient classification. Browser-normalizer-created products and returned native identifier observations currently have an explicit `ambiguous-unknown` disposition, with reason `NO_QUALIFIED_SHARED_CATEGORY_MAPPING`. Canonical concept, English preferred label and crosswalk remain null. The offline Python projector preserves source category fields and their provenance; it does not add a category disposition. A positive mapped or noningredient disposition requires independently qualified evidence; product names and unreviewed category tags cannot supply it.

Identifier disposition counts cover only returned occurrences in that response. Global coverage remains unknown. The offline adapter preserves the same fields and provenance states, and its OFF-specific contract version prevents stale cache reuse. Existing retained projections are unchanged, and omitted fields cannot be reconstructed by paging them. Current source-store qualification, reviewed versioned crosswalk and actual runtime adoption remain separate work. This change performs no source processing or normalizer restart.
