# Source category claims

New browser OFF projections retain supplied category and food-group fields, including unknown fields in those families, under `data.sourceCategoryClaims.fields`. Original text, codes, hierarchy arrays, language and supplied taxonomy version stay unchanged. The product record's existing provenance identifies the source and revision. `fieldStates` distinguishes supplied null, supplied values and fields omitted from this input. Omission does not establish absence in the original publisher record. Legacy `data.categories` remains compatible; the claim envelope preserves distinctions that its empty-array fallback loses.

Source categories describe the product. They do not establish ingredient composition, a canonical category or a noningredient classification. Normalizer-created products and returned identifier observations currently have an explicit `ambiguous-unknown` disposition, with reason `NO_QUALIFIED_SHARED_CATEGORY_MAPPING`. Canonical concept, English preferred label and crosswalk remain null. A positive mapped or noningredient disposition requires independently qualified evidence; product names and unreviewed category tags cannot supply it.

Identifier disposition counts cover only returned occurrences in that response. Global coverage remains unknown. Existing retained projections are unchanged, and omitted fields cannot be reconstructed by paging them. The offline adapter, current source-store qualification, reviewed versioned crosswalk and actual runtime adoption remain separate work. This change performs no source processing or normalizer restart.
