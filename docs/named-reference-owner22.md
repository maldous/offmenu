## Captured admission/context decisions

Own enumerable plain-object fields and dense array indices are captured before
asynchronous boundaries. Getters, custom plain-object prototypes, functions, nonfinite
numbers, cycles, sparse arrays, extra own array fields and excessive depth/size are
not accepted. Dense arrays with custom prototypes are normalized to fresh ordinary
arrays; inherited fields and methods are not copied or used as authority.
A bad registry cell is quarantined per metric
without invoking its accessor; valid independent cells can remain qualified.
Input/header budgets are20,000 nodes/250,000 string characters/depth32, with bounded
1000-key arrays/objects/cell counts. No input/callback/result mutable alias is retained.

Both owner decision functions receive a fresh detached binding:
{request:<captured full request>,registry:<captured profile/cells>,evaluatedAt:<clock>}.
They must return own data with status ('admitted' or 'compatible'), decisionId,
revision, exact full binding, checkedAt and validUntil. Canonical structural comparison
is only applied to captured finite plain data, so key order is irrelevant while
NaN/undefined/accessors cannot collapse into null. A copied arbitrary client approval
field cannot match a missing trusted registry/admission/context boundary.

Source admission is checked before forwarding issuer data to context qualification.
The explicit clock must be finite/monotonic and decision windows current. Admission
is checked again after context evaluation so an expired admission cannot survive
an awaited policy step. Windows are owner-supplied, not an invented TTL/source expiry.
Owner functions remain responsible for authoritative rights/withdrawal/epoch/version,
cohort/purpose/application/period compatibility and legal audience/field scope. This
is point-in-time consumption of injected decisions, not a CAS/store/auth producer or
an atomic guarantee against later upstream revocation. Existing store/CAS holds remain.

## Registry capture limits — current correction

Quarantined cells do not consume the accepted-data allowance of later valid
cells. Successful captures still share the existing 20,000-node and
250,000-character registry budget. A separate 200,000-node traversal allowance
includes the header and every attempted cell, including rejected cells and
repeated aliases. It is never rolled back. Exceeding it withholds the entire
registry before admission or context callbacks; no partial authority decision is
released from an exhausted snapshot. One oversized cell can remain isolated,
while repeated expensive failures cannot multiply work across all 1,000 entries.
This is a capture limit, not a wall-clock guarantee for caller-supplied hooks.

Synthetic regressions cover rejected character/node/cyclic cells in both orders,
the shared accepted-data cap, repeated expensive rejection in both orders, and
999 cheap invalid cells followed by a valid metric. These checks do not admit
real issuer data, source rights, runtime adoption or production use.
