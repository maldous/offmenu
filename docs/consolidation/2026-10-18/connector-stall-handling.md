# Connector operation checkpoints

Use one repository writer. Record each write target and expected content hash; reuse an existing exact Git blob. Yield promptly at the tool boundary and surface confirmed batch receipts. Investigate a genuinely stalled call around 60 seconds through available operation or approval status; do not send routine no-result updates to the user.

Respect pending approvals and stop on actual denials. If interruption is needed to recover tool control, treat the write outcome as uncertain and reconcile exact remote blob/ref/PR state before any retry. Never duplicate an in-flight request or change route to bypass a denial. A blob receipt is not a commit, CI result or merge.

Keep one coherent reviewed assembly and validate its exact SHA through full-checkout CI. Large files remain exclusively on the Foo runner under the owner’s latest direction; bounded sanitized hashes and provenance may remain in the repository. Classify by purpose without inventing a byte threshold. Verify custody before claiming Foo retention or deleting a local artifact. Update dependent guides and verifiers together when replacing bulk inventories with references.
