## What is actually wired locally

`createIdentitySession({sdk,flow,sessionFetch,onChange})` composes the installed SDK with the actual callback and request guards from immutable `5102bc7a42d7eab37522301705335acdf75c7b13`. The corrected `flow` additionally requires the companion `cancel` hook described below. Tests resolve only the retained guard/policy sources through read-only Git blobs and bundle them in memory. No legacy production auth branch is merged. The exact recovered Python fixture and all previous source snapshots remain untouched.

The local lifecycle explicitly connects:

- guarded callback processing to SDK hydration and signed-in notifications;
- SDK sign-in and logout to pending account state and invalidation of old UI/request leases;
- same-subject refresh/profile events to metadata updates without pretending that token rotation is an app-session epoch;
- cross-account SDK events to new leases, rejecting stale private response bodies through the retained `sessionFetch`;
- malformed, replayed and failed callbacks to empty local identity, with the retained flow responsible for URL/intent cleanup;
- logout to SDK-confirmed cleared identity. A successful SDK call that still reports a user raises `logout_incomplete`; it does not declare successful logout.

`current()` and `onChange` expose only `{user:{id,email,name}|null,pending,reason,clientGeneration,notificationFailed}`. The last field is a sticky presentation-failure boolean; it contains no exception/token details. This is a redacted local view, not server authentication. `onChange(view,isCurrent)` is a synchronous notification: any consumer doing asynchronous private UI work must retain/check `isCurrent()` before applying results. The adapter does not undo side effects a consumer already performed, and it does not claim remote request cancellation. `request(path,options)` is denied while signed out, pending, disposed, changing accounts, or intent cleanup is unconfirmed, and uses the retained account-bound guard for response/body reads.

`initialize`, `signIn(email,password)`, `startProvider(provider,settings)`, `logout`, `request`, `current` and `dispose` are the public methods. `sdk`, guarded `flow`, and `sessionFetch` are required dependencies, with no fallback to unguarded SDK callback processing. The supported SDK auth events are login/logout/token_refresh/user_updated. Metadata refresh cannot promote an absent/different local account. Disposal invalidates leases and ignores later events; it uses SDK unsubscribe if supplied.

This does not replace the server's fresh `verifiedUser`, issue a persisted app grant, revoke a provider credential, assign administrator roles, or establish member consent. Server epoch transport remains the independently reviewed state protocol/Owner02 integration lane.
