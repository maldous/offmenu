## Independent module contract

`integrations/request-budget.mjs` exports `createRequestBudget`. All clock,
storage and transport operations are injected; the module has no direct I/O or
dependency on Worker runtime APIs. Configuration is fixed per gate. The scope is
an owner-chosen opaque provider/billing-account identity shared by all matching
requests, never a query, IP, cache key, credential or personal-data value. Account
partitions must reflect the provider's actual quota account, not invented extra
allowances. All request paths using that account must use the same durable gate.

`storage.atomic(scope, update)` must serialize across processes/isolates, execute
the synchronous pure update against the latest state, persist its returned
`state`, and resolve with its returned `value` only after durable commit. It must
reject on failure. State is `{configuration,start,requests,spend}` and contains no
request payload. The test adapter is synchronous in-memory serialization only;
it is not a production storage implementation. Reads followed by independent
writes do not satisfy the contract. No Git fixtures or child jobs are used.

`spend` is an explicitly known nonnegative integer upper bound in owner-defined
billing units, including response-dependent charges where applicable. Missing,
fractional or unknown costs fail closed. Use `maxRequests: 0` or `maxSpend: 0`
to configure the corresponding zero allowance; zero-cost requests still consume
one request. A denied reservation returns an absolute millisecond `retryAfter`
at the fixed window boundary. Attempts are charged before transport and never
refunded on errors or revalidation. There are no automatic retries.

The owner must use this fixed-window policy only where it is at least as strict
as the provider's actual rules, with conservative ceilings and authoritative
clocks. Sliding-window, rolling, concurrency, token and cross-service quotas may
require additional gates. Configuration changes fail closed rather than reset
allowances; an owner-controlled migration is needed. Clock regression behind a
stored window also fails closed. Never rotate scopes or erase budget state to
obtain another allowance.

## Owner-controlled adoption (not shipped)

The existing resolver owners retain `cloud/enrichment.mjs`, schema, source data
and all policy custody. They can replace only the outbound fetch in its current
lease-held try/finally with a configured gate call, mapping the request to their
existing bounded transport. For example, after obtaining an admitted lease:

```js
const result = await gate({target, options}, {spend: configuredUpperBound});
if (!result.allowed) {
  // Return the budget denial; do not cache it as a provider failure.
  // Existing finally must still release this caller's lease.
  return budgetReply(result.retryAfter);
}
const r = result.response;
// Existing bounded parsing, normalization, policy recheck and cache write follow.
```

`gate` must be configured with injected durable atomic storage, trusted quota
configuration, clock, and a transport that issues exactly one attempt with manual
redirect handling. Permission/admission, account scope, consent, policy validity,
cache reads, retry/negative-cache TTL and lease acquisition remain upstream.
Persistence permission must still be rechecked after transport. Quota denial must
not be confused with empty provider data or cached as a provider error.

Conditional validators and 304 handling are deliberately not implemented here:
304 is returned untouched and consumes quota. The current route treats non-OK
statuses as failures, so owners must add valid retained-body/validator handling
before adopting conditional requests. Provider Retry-After, negative cache TTL,
and broader failure policy also remain owner integration work. A 429 is returned
untouched with headers preserved; this gate does not override that provider's
pause or authorize another attempt when it expires. Existing lease/coalescing
behavior remains the source of truth. No feature-shipped claim follows from these
unit tests.

The gate does not inspect or transform source records, quantities, uncertainty,
rights or nutrition/medical assertions. It grants no ownership, safety, purchase
or sharing authority. CACHE-02/CACHE-05 integration checks remain prerequisites.
