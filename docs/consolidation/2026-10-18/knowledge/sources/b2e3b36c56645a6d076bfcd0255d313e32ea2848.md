## Adapter and invariants

cloud/durable-budget-owner30.mjs exports durableBudgetStorage(db), compatible
with the old helper's synchronous storage.atomic callback. It reads a versioned
row and commits its transition via a conditional UPDATE or conflict-safe INSERT
RETURNING. A stale version reruns the pure callback, at most 16 attempts by default
(maximum 64); storage errors and exhausted retries reject with no allowance.
No callback may dispatch transport or have external side effects. No multi-call
read/modify/write sequence is presented as a database transaction: each successful
CAS SQL statement is the transaction/linearization point. An ambiguous committed
write may remain charged; that is conservative, never a refund.

The additional durableQuota consumer records reservation receipts in the same
state transition as request count and integer cost. Only dispatch:true permits
one provider attempt. Identical attempt ID/fingerprint/cost returns dispatch:false;
changed content for the same ID rejects. There is no transport retry or response
cache, and no exactly-once claim for external requests. Crash after reservation
may spend allowance without making a request. Unknown, fractional, negative or
missing upper-bound prices reject; explicit zero is valid only if the owner can
establish a zero price. Caller must supply trusted pricing, not browser input.

Quota windows use fixed clock buckets. Configuration change and observed clock
regression reject. pauseUntil stores the maximum absolute deadline and survives
window rollovers; repeated calls cannot shorten provider backoff. Owner must use
an authoritative clock and ensure fixed-window ceilings meet the provider's actual
quota, adding rolling/concurrency/daily gates when required. Account scopes must
reflect actual billing/quota accounts across ALL callers, never rotated by query,
IP, credential change or retry. Receipt TTL must be at least windowMs. Expiring a
receipt never refunds counters. At most 128 receipts are retained; capacity denies
additional attempts rather than evict live dedup records. Expired IDs are forgotten:
callers MUST reject retries older than receiptTTL and never reuse attempt IDs.
Fingerprint and attempt ID must be opaque bounded digests, without personal data
or credentials. The module does not authenticate the scope or grant source rights.

2. Supply a trusted provider-account scope, authoritative integer price upper bound,

   Never accept arbitrary prices/IDs from a client. Missing prices disable fetch.
3. After source permission/dependency verdict (Owner29), cache freshness, existing
   retry check and lease acquisition, call quota.reserve. On dispatch:false return
   a bounded denial, releasing the lease in existing finally. Do not cache quota
   denial as missing provider data or as provider failure. For a duplicate, use
   existing cache/refresh state; no second provider call is permitted.
4. Only on dispatch:true issue one existing bounded, manual-redirect fetch. All
   failures, 304/429 and ambiguous outcomes retain the charge. Before cache writes,
   repeat existing permission/account/consent/withdrawal checks. A validator/304
   response needs retained-body handling owned by the resolver, not this adapter.
5. On 429/Retry-After or existing exponential error backoff, call quota.pauseUntil
   with the later authoritative absolute deadline BEFORE admitting further
   attempts. Existing in-flight calls cannot be cancelled retroactively. If pause
   persistence fails, fail the provider path closed; do not silently continue.
6. readback uses a CAS transition and returns current counters/receipts/deadline;
   it is an operator check, not public disclosure of account usage or reset API.

Example after all owner-controlled checks and lease acquisition:

```js
const storage = durableBudgetStorage(env.DB);
const quota = durableQuota({storage, scope: providerAccountScope, clock: Date.now,
  windowMs, maxRequests, maxSpend, receiptTTL});
const decision = await quota.reserve({attemptId, fingerprint, spend: trustedUpperBound});
if (!decision.dispatch) return quotaDenial(decision); // lease finally still runs
const response = await boundedProviderFetch(); // one charged attempt
// owner handles error deadline + quota.pauseUntil, permission recheck and cache
```

Do not run both the old helper's budget gate and durableQuota for the same attempt
or share their incompatible state formats under one scope: select one consumer.
The storage adapter alone may be used with the old helper if idempotency is not
needed, but that helper does not gain attempt dedup/backoff from storage alone.
