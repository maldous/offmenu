Contract version: `offmenu-mocks/1`. Synthetic development fixtures only. This mock pack is ready for review; provider, Google OAuth, application and production acceptance are separate gates.

## Validation

From permanent Worker 06 root:

```
node --test dev/wiremock/validation.test.mjs
node dev/wiremock/runtime-validation.mjs dev/wiremock/.cache/wiremock-standalone-3.13.2.jar
node dev/wiremock/coverage.mjs
```

The unit suite tests 17 contract representatives across seven scenarios on a test-owned loopback HTTP transport, plus URL/credential rejection, timeouts, redirects/unmarked response blocking, corpus checksums, deterministic mappings and boot/PID custody rejection. The real-runtime harness launches checksum-verified Java WireMock on explicit loopback port 19066, tests those 119 representative scenarios, binary corpus checksums, unmatched requests, journal preservation/reset, owned shutdown and retained evidence hashes. It refuses a busy port, shuts down only its verified runtime, and never falls back to live provider calls. Readiness/validation failures retain evidence; no arbitrary process signals are sent. Neither suite qualifies every method/path/actor combination or application integration.

`coverage.json` is deterministic matrix output. `verification.json` records actual checks and immutable external receipt hashes. Runtime logs and JSON receipts stay under ignored `.runtime/`, JAR under ignored `.cache/`; do not add these large artifacts to Git.

The exact public 18.6 MiB WireMock 3.13.2 JAR was downloaded from `runtime-lock.json`'s Maven URL with a 64 MiB/60-second bound and matched the pinned SHA512 before use. The runtime tooling never downloads dependencies; reuse this verified artifact or supply the same pinned bytes.

## Runtime custody

```
node dev/wiremock/runtime.mjs start 19066 /absolute/path/to/wiremock-standalone-3.13.2.jar
```

Start remains in the foreground. It verifies SHA512 and port availability, creates a unique `.runtime/run-19066-<UUID>` evidence directory, writes versioned mappings, and starts Java bound only to `127.0.0.1`. No proxy, recorder, webhook or arbitrary launch-argument option exists. Linux boot ID, PID birth ticks, jar/root/cwd/port, version, mapping digest and per-run health token are recorded in an exclusive, read-only `custody.json` before readiness polling. The ready receipt supplies that path; use it explicitly for subsequent commands:

```
node dev/wiremock/runtime.mjs status /absolute/path/to/run-19066-UUID/custody.json
node dev/wiremock/runtime.mjs reset /absolute/path/to/run-19066-UUID/custody.json
node dev/wiremock/runtime.mjs audit /absolute/path/to/run-19066-UUID/custody.json
node dev/wiremock/runtime.mjs stop /absolute/path/to/run-19066-UUID/custody.json
```

Every operation checks the worker-local custody path, boot ID, PID birth, Java jar/root/port/bind arguments and loopback health token before administration. Reset saves the current synthetic journal to an immutable audit receipt, restores the file-backed mappings, resets scenarios and clears the journal. Do not edit runtime mapping files outside this tool.

Stop saves an audit receipt, uses the owned server's admin shutdown endpoint, and confirms process disappearance before writing an immutable stop receipt. The foreground launcher also writes an exit receipt. **No evidence directory is deleted.** Status/reset/audit/stop receipts use unique filenames, exclusive creation, read-only permissions and reported SHA256 hashes. Local filesystem administrators can still change permissions; these are application-level immutable records, not cryptographically signed storage.

Use only synthetic traffic; journals include request bodies and must remain local. Health probes also appear in the journal. Interrupted/failed startup retains custody; review boot/PID identity before recovery. No automatic restart, orphan cleanup or signaling is provided.

Admin semantics: https://wiremock.org/docs/standalone/administration/ and https://wiremock.org/docs/stubbing/. Standalone binding: https://wiremock.org/docs/standalone/java-jar/.

## Integration and coverage boundaries

`createOutboundAdapter` accepts a Request and returns a Miniflare Response for the Development Environment owner's fetch seam. Contracted HTTPS provider requests reroute to an explicit loopback mock origin. Unknown hosts/methods/paths, ambient cookies, real credentials, unmarked responses and redirects fail with 502. Timeout returns 502 with a blocked audit event; error/auth/rate-limit fixtures return 503/401/429. Audit events contain host/path/method/contract/status and rejection reason, not headers or bodies. There is no live fallback. This is a routing boundary, not an operating-system network sandbox.

Use synthetic `fixtures.mjs` actors/bindings and the authored one-record corpus. Token fixtures currently cover form password/refresh for Alice/Bob/admin; signup returns Alice. Update and Google authorize/callback return explicit 501. Worker 04 owns auth QA and token/interface alignment; do not broaden OAuth acceptance here.

Worker 05 owns composition of the app fetch seam; Worker 07 owns common corpus transport and exact common-data alignment; Worker 08 owns cross-component acceptance. Unseeded common-data/release requests remain blocked. Coordinate shared interfaces through Morgan/Gateway without editing other owners' source.

Browser integration requires a fresh Playwright context with `serviceWorkers: 'block'`, WebSocket routing support, and audit installation before navigation. Only the explicit local app origin continues directly. Contracted browser dependencies route through mocks; WebSockets close. The adapter cannot prove the caller's context option, and full browser acceptance remains a gate.

D1, local storage/cache resets, scheduled cleanup, devices, Google consent and provider dashboards remain owner boundaries listed in `contracts.json`. No production or vendor acceptance is implied.


## Identity fidelity correction: W10-F2/F3

`offmenu-identity-session/2` supplements API `offmenu-mocks/1`. Token grants require form encoding, unique exact grant-specific fields, and fixture credentials. Missing/empty/wrong credentials and missing/unknown grants return 401; duplicate keys, mixed grants/credentials, extra fields and non-form bodies return 400 before transport. Successful mappings independently match every complete required field, not a username substring; malformed direct WireMock forms fall back to marked 401 and never issue tokens. Valid fields are canonicalized, so reordered/percent-encoded input remains usable through the adapter.

Each actor has a WireMock Started/Revoked scenario shared across fixture response scenarios. Fixtures initially have usable fixed tokens. Successful logout revokes only the authenticated actor: both user lookup and refresh become 401; other actors remain valid. Repeated or unknown logout is 401. Only a valid successful password login revives that actor. Error/auth/rate-limit/empty/timeout fixtures do not change session state. Owned reset restores initial session state after preserving the journal. This models fixed-token, per-actor revocation, not token rotation, generations, per-device sessions or provider acceptance.

Confirmed shared guarantee with Worker 04 candidate `5102bc7`: exact grant credentials and unique fields, actor-scoped logout revocation, other-actor preservation, password re-login. Deliberate differences: 06 refuses extra fields/non-form token requests; 04 permits unique unused form keys. 06 successful logout is 200, 04 is 204; both are SDK-compatible 2xx. 04 has synthetic same-origin authorize revival; 06 authorize/callback remain 501. Existing signup/recover/verify fixtures are not shared 04 capabilities.

`identity-validation.mjs` adds real Java checks for all three actors, direct malformed WireMock grants, adapter rejection, logout/user/refresh denial, invalid-login non-revival, other actors, error-scenario non-revival, password revival, and reset restoration. See `identity-verification.json` for immutable regression receipt hashes. Historical `verification.json` and all prior native runtime/custody/audit files remain unchanged.
