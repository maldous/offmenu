# Worker61 storage guard correction for exact Worker60 re-review

Prior candidate `a774f3df1e330ae4181fb60a0a70ce77164b5133` remains an immutable parent. Its measured JSON is unchanged. The old guard opened files before capacity refusal, accounted zero for empty-file inodes, and used per-writer byte counters. The retained before fixture reproduced eight zero-charge files plus an empty refused path. Neither it nor an arithmetic pass established a safe next importer run.

The replacement SharedBudget holds one `flock` on a preallocated, fixed-size JSON ledger throughout each managed file creation/allocation/write. All four categories and cooperating processes consume that ledger. Root directory and control ledger bytes/inodes are included. File reservations charge one inode and the entire rounded maximum physical file allocation plus 64 KiB overhead before opening its path. Ledger receipt capacity, batch bytes/inodes/record reservations, and fresh user-available filesystem reserves are checked before creation. Empty files consume an inode and a preallocated block. `posix_fallocate` allocates actual filesystem blocks; st_blocks readback is verified against the envelope. Files retain padded preallocation; consumers must use the recorded payloadBytes rather than treat padding as data.

Default and maximum proposal ceilings are **238,354,432 bytes, 4,016 inodes and 1,000 declared records**. Required reserve minimums are **10 GiB and 10,000 inodes**. Each file's bound includes metadata slack; the ledger has a separately charged control/directory envelope. Smaller caps are allowed for isolated tests, smaller reserve requirements are refused. Reservations remain charged with no deletion/reclaim/hardlink discounts. A failed or interrupted managed operation leaves the ledger blocked/active; a new process refuses it rather than forgetting the pending allocation. Unknown/missing paths, changed file identity or physical bounds, corrupt ledgers and target inode/device changes refuse. The destination must be a caller-owned private existing directory.

This is a cooperative managed-writer guard, not a kernel filesystem quota or authenticated lease. Whole-host external writers can consume space concurrently; fresh reserve checks run before creation and after managed writes, and stop on lost reserve. The physical envelope relies on the backing allocator supporting bounded POSIX preallocation; an allocation exceeding its envelope poisons the guard and is never accepted. These limits must receive exact independent review. Declared record reservations require owner-side input counting; the byte writer does not infer normalized rows from arbitrary bytes.

**SQLite, journal, temp and arbitrary subprocess/importer writers are refused.** Merely naming an external writer's category does not grant a reservation or controlled-writer status. Existing importer01 is unchanged and cannot be run under this candidate. It needs a controlled integration or separately established hard allocation boundaries covering every writer, including qualification sorts/temp and checkpoint journals. Historical measurement rerun is disabled at entry before any target work. Existing measured61 source/output/SQLite fixture results are preserved as historical observations, never promoted to full-run clearance.
