## Local use

From this checkout:

    node scripts/recipe-pack-owner31.mjs --output /absolute/new/recipe-pack.html

Optional --input points to an exact copy of the reviewed public/recipes.json;
its complete byte hash MUST match before output is generated. The default input
resolves relative to the script, not process cwd. Input bound is 2 MiB. Output
requires an explicit .html path and exclusive creation; existing files are not
overwritten. CLI JSON reports source/output hashes, exact record IDs and counts.
No network, browser launch, paid tools, new packages, acquisition or credentials.

Open the generated HTML locally and use the browser Print command for paper or
a local PDF. Print CSS supplies A4 margins, recipe page breaks, wrapping text,
repeated table headings and rows protected against splitting. Browser visual
pagination has not been independently exercised; no PDF artifact/certification
is claimed. The generated document uses no JavaScript, external assets, forms,
images or routes and has a restrictive meta CSP.

## Preservation and unknowns

optional flags, instruction order, recipe version, attribution, review state,
quantitiesValidated source flag and notes are rendered as source data. No
serving scale, pack rounding, conversion, edible-portion, intake or nutrient
calculation is performed. JSON numeric values use ordinary decimal display
(e.g. source 150.0 prints 150, same value); this is not source-lexeme facsimile.
Source byte hash binds the original representation.

Missing values print "Unknown (not supplied)". Incomplete selected recipes stay
included and carry explicit missing-field reasons; no default quantity/yield/
preparation/instructions are invented. Zero and false are printed as recorded,
not replaced by unknowns. All thirty actual selected records have the displayed
core fields; that is not independent kitchen validation. Each recipe retains:
"Original practical recipe; quantified and schema-checked. Not independently
kitchen-tested. Pack cooking instructions take priority. Water used for boiling
is not assumed fully consumed." The cover repeats the kitchen-testing caveat.

An escaped full-record disclosure preserves all additional original fields and
nulls for on-screen audit; that disclosure is intentionally omitted from print.
Core requested recipe/preparation/attribution/version/notes remain in print.
All source/provenance text is escaped, with no executable HTML or source URLs
turned into links. renderStarterPack is a pure presentation function for local
fixtures; only generateFromPinnedInput/the CLI enforce the actual reviewed
input hash. Rendering a fixture does not qualify its source.
