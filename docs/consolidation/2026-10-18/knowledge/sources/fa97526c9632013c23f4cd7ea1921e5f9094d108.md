## Findings and adoption limits

Account/member: the envelope owner/memberId/revision must exactly match injected trusted context. Consent binds owner/member, purpose, source, type and unexpired UTC time. Cross-account/member mismatches fail closed. The function deliberately does not authenticate or verify account membership. Host owner04 must supply current member authorization, including child-specific scope, rather than derive context from upload booleans or household membership alone.

Source identity/revision: sourceId/exportId and sourceRecordId remain separate. Duplicates are detected within this preview only. Envelope revision is the account import revision, not a source-issued row revision. There is no persisted replay key, cross-export/source overlap query or row-revision/withdrawal vocabulary. Those are missing consumer responsibilities; no auto-join by names/value is justified.

Dates/units/unknowns: strict canonical UTC timestamps and a finite trusted clock reject impossible/future dates; units match existing eight health types with no conversion. Missing/null values go to rejected indices, not zero-valued records. This contract cannot retain source time-zone/offset, interval bounds, origin device/vendor identity, raw numeric lexemes or native source-revision metadata because those fields are not admitted. Rejecting unsupported fields is safer than stripping them silently, but a native provenance extension must be separately reviewed before those claims are supported.

Overlap: source/type identity dedup only applies inside the packet. Different-source measurements can both be previewed; the overlap string warns against sums, it is not an enforcement mechanism. Owner34 activity schedules describe planned intervals, not measured totals. The consumer must obtain exact measured interval/member/type identity and current persisted observations before any reviewed overlap decision. Unknown interval boundaries cannot be fabricated from the single observedAt field.

Revocation/admission: preview has writes=false, private visibility and imported-unverified status. It checks present consent at preview time but has no durable grant withdrawal, deletion or persistence transaction. needs-review partial results must not be committed automatically. A host must confirm the exact accepted subset, then revalidate consent/member/session/version and persist atomically. Rejected-row reasons contain indices and descriptions, not raw health values; upload retention needs account-private policy.

Mutable context: serialized input parses into a private tree and the pure function is synchronous, with no asynchronous race inside the validator. Trusted context must still be constructed from immutable current policy facts, not accessors or caller metadata; never retain a preview across a consent change as write authority.
