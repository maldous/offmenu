## Consumers

`contract.json` is the versioned transport artifact for Workers 05/06; `contract.mjs` exports `ACTORS`, `publicActor`, `identityToken`, and `CONTRACT`. All three actor objects were independently compared with Worker 06's `dev/wiremock/fixtures.mjs` and match exactly. They are synthetic credentials, not real JWT verification or provider-managed account linking. Do not substitute real credentials.

Worker 05 can use these actor IDs, bearer/refresh values and route semantics in its same-origin isolated runtime. Worker 06 owns any changes to its provider mappings, currently returning 501 for browser OAuth. Google authorize in this adapter redirects only to its own `/` fragment and rejects unknown/duplicate query fields, including attacker-specified destinations. Browser callback handling uses the checkpoint's actual `identityFlow` and installed Netlify SDK. The fixture port is not a production OAuth endpoint.

The `/api/state` response adds a QA-only `owner` field to make isolation observable; storage is memory per actor and disappears on close. The fixture validates identity, origin, bounded body and revision, not the complete production state schema. It intentionally does not simulate care/integration/provider routes: unmatched requests return 404 with no network forwarding. Profile updates, signup, recovery, verify and server callback are unsupported (501). Real Google consent, linking and recovery/invitation qualification remain separate.

## Run and custody

From the permanent Worker 04 checkout:

```sh
node dev/google-idp/adapter.mjs worker04-google-qa-<fresh-suffix>
```

Use a fresh suffix. Default port `0` asks the OS for a free port; an optional third argument selects an explicit port and fails if occupied. Bind is always `127.0.0.1`. The first JSON line records owner, namespace, root, origin, PID, session, start time and checkpoint. Open only that origin in a new named browser context, blocking every other origin before navigation. Use the recorded terminal to close only this instance; the program also exports `startAdapter()` and an awaited `close()` for runtime/test custody. There is no installation, D1 access, live fallback, or persistent credential/state storage.
