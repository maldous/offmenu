## Owner-controlled adoption contract

The module is an additive, pure adapter, with no network/storage/clock dependencies.
An existing catalogue caller could adopt it after owner review:

```js
import {referenceViews} from '../public/reference-profile-model.js';
const calculation = calculateBasket(admittedBasket, metricDictionary);
const presentation = referenceViews(calculation, {
  serving: admittedServing,
  referenceProfile: selectedSharedAnalyticalProfile,
});
```

The catalogue/UI owner must supply and review the evidence, authorize exposure in
the same account scope, retain consent/rights restrictions and add it to the caller.
Existing app/UI/auth/schema/source data are unchanged; no caller imports this module yet.
Source identities and quantities are preserved in `calculation.lineage`; arbitrary
caller custody metadata and all supplied basis evidence are cloned and retained.
This retains restrictions without evaluating or granting permissions.

Input is a bounded `basket/1.1` calculation result. Serving evidence requires sourceId,
recipeId, recipeVersion, matching basketId/basketVersion and preparation state, and
exactly one positive `fraction <= 1` or measured `massG <= calculation.massG`.
The caller must verify that the identified recipe version actually produced this
basket and that the fraction is defensible; the adapter cannot authenticate declarations.

Reference evidence requires system, id, name, version, lifeStage, sourceId,
`basis: 'person-day'`, and metric `{value, unit, definition, status: 'complete'}`.
The value must be finite and positive, unit/analytical definition must match, and the
calculation population must exactly equal the named life-stage token. No mixed
population inference or energy-based adult-equivalent substitution is performed.
Local values remain separate; a caller must select the shared analytical profile.
Before comparing reference percentages, the comparison owner must enforce equal
`referenceProfileKey` (system/id/version/lifeStage), the existing cohort/state/purpose/
track and nutrient-definition gates, and source/rights eligibility. This adapter
does not compare baskets, rank results or replace `compareBaskets`.

Each metric exposes all seven views with value, unit, available/withheld status,
reason and explicit denominator. Partial/conflicting numerators withhold values;
known subtotals and missing IDs survive in the original calculation. Missing/zero
denominators remain null/zero in the denominator record and never become default
person-days/servings/reference values. A measured zero nutrient can remain zero.
Serving fractions are independent of energy completeness. Reference needs a complete
person-day amount and compatible named target. Finite arithmetic is required.
