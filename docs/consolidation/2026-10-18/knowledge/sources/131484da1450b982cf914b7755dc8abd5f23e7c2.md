## Storage/schema and reproducibility

[Full metadata inventory](actual-recipe-inventory-owner07.json) records every inspected detail path, compressed byte size/hash, per-file count/read status, SQL path/query and index hash, field/schema inventories, source-origin counts, licences/visibility declarations, overlaps, raw acquisition metadata and UTC readback. It contains no copied directions, ingredient values or raw recipe records.

Normalized JSONL lines may be arrays of records; curated lines are `[bundleKey,[records...]]`. Recipe details expose `data.name`, `languages`, `ingredients`, `directions`, `yield`, `quantityCoverage`, `reviewStatus`, `qualificationStatus`, source publisher/limitations; ingredient quantities retain source notation and unresolved matches. Provenance includes source/origin source, record ID, revision/content hash, URL, licence/rights URL, attribution and visibility. Raw historical objects instead expose `title`, `slug`, `collection`, `body`, author/culture/year/source URL/licence metadata. Common graphs contain recipe variants, incomplete historical candidates, concepts, steps and assertions; those resource counts are projections, not additional bodies.

Read-only SQL used existing indexes:

```sql
SELECT source,kinds,count(*) FROM entries
WHERE source IN (?, ...) GROUP BY source,kinds;
```

Connections used SQLite URI `mode=ro` and `PRAGMA query_only=ON`; SQL totals are bundle-index counts and were corroborated with detail reads. JSONL was streamed and parsed to EOF, with gzip integrity validation and exact retained-byte SHA-256. No reload, repair, source checkpoint write, decompression to disk or corpus copy occurred.
