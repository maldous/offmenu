## Contract

`createD1SessionStateProtocol({database, authenticate, readSession, authorizeRequest, authorizeEnrollment, audience, realm, ttlMs})` returns async `enroll/read/mutate/status/revoke`. Await every call. Error code/status/outcome and successful binding/operation/revision/digest shapes follow reviewed 25543. `database` must be native D1 with `withSession`; there is no synchronous transaction callback adapter or fallback.

Every action freshly authenticates the subject and requires literal-true request policy. Enrollment separately requires literal-true server enrollment policy. The synchronous protected transport parser captures session ID, capability, epoch and realm before any await; mutation captures/validates the private command JSON before any await. Caller must supply bounded body parsing, exact methods/resources/Origin/CSRF, secure credential transport and enrollment limits. Synthetic fixture headers/JSON are not production authorization.

`SESSION_STATE_D1_DDL` describes two new isolated tables. Apply only through a separately reviewed migration; module never initializes schema. It consumes existing `user_state(user_id,revision,state_json,updated_at)` without changing its schema. No handler may bypass admission after adoption.

Each action creates a `first-primary` D1 session. Mutation batch inserts one guarded terminal ledger result, applies initial INSERT or revision CAS UPDATE only for its unpredictable per-call commit token, asserts resulting revision and serialized payload via a NOT NULL SQL guard, and reads the admitted result. The guard forces whole-batch rollback even if a trigger ignores the write. Exact retry tokens cannot replay the state write; different digest under the same operation ID is rejected. Conflicts record the pre-mutation current revision, including zero for absent state, and remain terminal.

Admission predicates match authenticated subject, capability hash, scope, audience, realm, epoch, live status and database-clock expiry in SQL. Stored revision must be a safe positive integer, with zero reserved for absent state. Revoke performs guarded durable tombstone/epoch increment and same-batch readback; repeating the original authenticated capability returns the original revocation. It affects one app session, not other sessions or the provider account. A revoke completed before a pending authentication resumes prevents that mutation's admission. Batches serialize CAS and ledger atomically; no JavaScript pre-read is used as authority. An expiry crossed after a newly inserted operation but before final read is reported storage-unknown, not proof of no execution.

Enrollment expiry is bounded TTL from Worker clock; admission/revocation uses database clock. There is deliberately no injected fake clock. Restore requires a fresh independently configured realm. D1 transport failure always reports unknown; status can recover a committed result only under still-live admitted credentials. A revoked session cannot disclose its cached outcome. Retention, global revocation, per-member consent, schema extensions and provider revocation are not implemented by this adapter.
