# Normal-user global collection handover

The same deterministic entrypoint supports `--mode user` and `--mode runner`.
No arguments retain the existing runner behavior. The source selection, all 4,753
known asset units, 249 countries, 3,237 country/type cells, fixed holds, ten exact
prospective contracts, resource-aware parallel acquisition/preparation and output
limits are shared. Neither mode discovers sources or changes permissions.

User mode resolves the invoking non-root account's home from the account database
and uses the stable `~/src/offmenu-data/owner-collection-runtime` directory. The
existing `~/src/offmenu-data` parent must belong to that account. New custody
files and directories are private. Source fingerprints, failed intents, originals,
physical reservations and preparation receipts persist across checkout versions.
A repeated invocation does not repeat successful or uncertain source transfers.

The pinned `owner-local-global-20261018-001` handover binds all ten source contracts
and the five exact historical failed intent/detail/contract hashes. Before user
acquisition, the existing authenticated GitHub route checks that the current
source-bound dispatch hold still agrees with that immutable handover. Root must
not submit an overlapping runner collection until the actual manual outcomes
have been reconciled and imported. This does not assert a universal native-worker
census or empty native catalogue.

Each source freshly checks the existing native metadata claims directory and
stable owner-local claims while holding the existing serialized admission lock.
Exact URL aliases and URL-derived claim filenames are checked. A real claim,
partial, reservation or uncertain same-source state blocks that source. Readable
historical runner roots are also checked. Only a genuinely absent or
permission-inaccessible historical runner root can use the exact documented
handover evidence; unsafe paths, other I/O errors and changed predecessors block.
Historical runner files are not copied, rewritten or relabeled as user-owned.
The additive successor records the real invoking UID and handover identity.

Existing native originals remain at their recorded paths. Owner-readable and
permitted originals can be verified/prepared; inaccessible originals produce
explicit outcomes. Raw originals and derivative contents remain on Foo.

User mode saves a complete closed manual result before automatic publication
using the existing `gh` login. The private repository receives bounded sanitized
metadata, complete asset/stage and country/type outcomes, source pins, custody
paths and checkpoint hashes. No Actions run identity or Actions receipt is
invented. Publisher failures retain local results. `--mode user --publish-only`
loads the stable saved result and retries publication without entering any
acquisition or preparation path; an uncertain GitHub update is reconciled before
any new update. The complete immutable source checkout and final command are
provided with the reviewed source commit. No package installation or new credentials
are part of that command.

## Repeatable owner launcher

The reviewed `scripts/run-global-on-foo.py` provides one-time `--install COMMIT TREE`
setup into the private `~/offmenu-global-collection` directory. Setup verifies the
exact detached checkout and every reviewed dependency, and refuses mismatched or
unsafe existing installations. It does not invoke collection. After setup, run
`~/offmenu-global-collection/run` from any directory. Publication-only recovery is
`~/offmenu-global-collection/run --publish-only`.

The launcher retains existing `GH_TOKEN`/`GITHUB_TOKEN` credentials only as inherited
environment values; they are never command arguments or saved in files. GitHub
configuration location is retained, while unrelated Git, shell and Python
configuration variables are removed. The global entrypoint removes both token
variables for the entire acquisition/preparation worker phase and restores them
in a `finally` block for GitHub publication. No credential creation/login occurs.
The initial delivered launcher failed before acquisition because its clean
environment omitted the owner's existing `GITHUB_TOKEN`; this corrects that
handoff without changing source selection, custody rules or dataset permissions.
