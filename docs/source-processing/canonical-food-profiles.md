# Canonical food assertions and private dietary rules, v1

Two **optional** profiles extend the existing contracts. The public assertion is a cited numeric fact; the personal profile contains a person's own planning choices. Neither is a new corpus, a generalized permission grant, or an assertion that a recipe is safe. The public schema rejects private profiles and extra keys. Public adapters do not import the private evaluator.

## Public fact and statistic

Each assertion identifies a stable subject, property and field, original quantity/lexeme and all comparison axes. The field map covers **every scalar** of subject/property/pointer, numeric value and unit, adjustment basis, provision type, issuer, jurisdiction, population, life stage, edition and effective dates. Entries name their actual source citations. The source adapter validates real source coordinates/values and supplies trusted per-observation witness digests, exact external URL/host, allowed purposes and operation-specific transformation pins separately. A record cannot authorize itself. A schema pass alone is not source verification.

The pure Python API in [canonical_food_profile.py](../../src/offmenu/refresh/canonical_food_profile.py) converts only known dimension-compatible units using exact rational factors. U.S. and imperial fluid ounces have different codes; an ambiguous cup/ounce, volume↔mass, arbitrary “serving”, ambiguous energy or unmeasured density is rejected. Display locale is not an input to the arithmetic. Keep source notation. Any further rounding must be labelled as presentation, not written back. Nutrient composition measurements are not population recommendations.

Unweighted mean and median are explicit reviewed method choices, not default reconciliation. Distinct observations must describe the same exact subject/property, nutrient form, jurisdiction/issuer, population/age/sex/life stage, definition, edition/effective span, period, preparation and normalized basis; fields marked unknown are not comparable. Overlapping quantitative upstream occurrence IDs, native source coordinates or identical physical asset/record/field coordinates are refused, even if the copied records have different filenames. Return the exact fraction, units, n, method pin, input assertions/field origins and conversion factors. Do not average competing authoritative recommendations across jurisdictions. The result remains a candidate; it cannot publish itself. Source-native clinical thresholds or multiple official variants remain separate facts, never user constraints by default.

Retain external image references under distinct image rights; a client may link a separately permitted provider-origin image. If the original cannot be rendered under current rights, use an appropriate Unicode symbol, then the local logo. No data file, image mirror/proxy, rehosting or redistribution is introduced. Public translation requires separate rights plus source-text commitment, source/target language, exact method/model/term/version/review. It must not rewrite numerical fields or obscure the original citation.

## Private plan

The private [evaluator](../../src/offmenu/refresh/private_dietary_plan.py) takes a member-controlled rule version, proposed menu/day entries and an external authenticated permission/plan snapshot. Bind the currently entitled account, household, member, consent, purpose, profile digest/revision, session generation and current time. A snapshot from another member/session, a withdrawn grant or a modified candidate plan is refused. Verified recipe variants and their field-level source receipts are a separate trusted input, not user-provided evidence of safety. A browser-facing caller must recheck revocation and audience before display, cache reuse or export. Never transmit private rules, identifiers or readings to a public provider or translation service.

A required ingredient/attribute declares whether any item in the period or every item must satisfy it; an exclusion applies to every item. A partial plan window is never eligible for selection, even if every visible serving seems to pass. Rules may require/exclude a known ingredient or attribute, or set an inclusive/exclusive nutrient maximum/minimum in an explicit unit and period. Per-recipe nutrient amounts require a known verified positive serving yield. Day/meal totals also require the actual planned quantity. Unknown, conflicting, failed and met are distinct. Missing ingredient evidence is **unknown**, not absent. Nutritional values are not filled from a different edition or guideline. Day buckets use the plan's verified member-local calendar; the application must derive this membership from the actual calendar/timezone. Preferences rank qualifying candidates; they never override a hard conflict, failure or unknown. Plan and evidence explanations are for the authorized person only. No clinical advice.

## Interoperability and acceptance boundary

[Schema.org Recipe](https://schema.org/Recipe), [MenuItem](https://schema.org/MenuItem) and [NutritionInformation](https://schema.org/NutritionInformation) are useful exchange shapes, not source or consent authorities. [UCUM](https://ucum.org/ucum) informs explicit unit notation; the subset here is not a general UCUM parser. [GS1 Digital Link](https://ref.gs1.org/standards/digital-link/) distinguishes product identifier syntax from evidence that two source observations are the same product. [FAO/INFOODS](https://www.fao.org/infoods/infoods/standards-guidelines/en/) is relevant to food matching and nutrition-expression bases. [PROV-O](https://www.w3.org/TR/prov-o/) separates observed entities, derivation and activity; [ODRL](https://www.w3.org/TR/odrl-model/) describes rights and restrictions, not implicit permission. [FHIR Observation](https://hl7.org/fhir/R5/observation.html) and [Consent](https://hl7.org/fhir/R5/consent.html) are private interoperability comparisons only. None implies certification or automatic conversion.

This slice is source and synthetic behavioral qualification, not a deployed planner, direct provider execution, or a claim of complete dataset coverage. Public assertions and private rules need independently admitted production bindings, authenticated storage and served UI/menu/preview/multi-day caller qualification before an end-to-end acceptance claim. Do not reopen UIF-100 or confuse the tested rules with treatment advice.
