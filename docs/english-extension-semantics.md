# Linked English extension: bounded semantic resolver boundary

This is the Worker19 F1/F2 successor to proposal manifest37176706, after independent Worker56 review9525. It is a minimal, unregistered callback candidate, not an English corpus, production resolver, graph mapper, admission or activation. Existing00 integrates reviewed source; fresh56 review is required. Source/operation/privacy/no-read/custody/denial/production/CIX holds remain. No real source body, cache envelope, translator/model/API or dataset is exercised.

## Baseline and compatibility

Author base is accepted develop4e654924a5362707b6ecfaab6847ee302eadc11b, verified from Gateway's fresh origin/local evidence9570 and actual HEAD before work. It includes reviewed PR59: parser1.3.2, assistant transform1.0.2, cache2. This callback consumes an already qualified parsed artifact; it does not reinterpret or replay caches or migrate old envelopes. The separate new proposal-2 schema preserves all original closed field shapes, with version/identity pins advanced to this baseline. The original proposal-1 packet remains immutable. Stale parser/transform inputs are held, not silently reclassified as corrected.

`EnglishPolicy` pins reviewed application schema/policy, original Asset, exact parsed Asset and record format/line/pointer/ID, and the existing input SourceContract. These are caller code inputs, never constructed from the source sidecar or a CLI plugin. The source artifact still needs its independent extraction/encoding/grant/provenance qualification under the current parser/cache contracts. This module is not a replacement extraction validator.

## API and existing execution boundary

`validate_extension(extension, policy, resolver)` returns a tuple of fixed diagnostic codes. It is pure with respect to caller documents: it neither changes them nor opens paths, writes files, fetches data, allocates IDs or emits graph records. `semantic_validator(policy,resolver)` adapts it to the existing reviewed `SourceContract.semantic_validator(row)` callback using the native sourceAssertion wrapper's data field. Existing `qualify` remains responsible for exact input inventory/bytes, independent count/IDs, schema checks, record provenance, resource limits and pre/post byte checks. No production factory, registry binding or accept invocation is installed.

The schema is closed and uses only local references; its canonical fingerprint is pinned in policy. The extension/evidence bound is8MiB by default, matching the existing record bound. Output diagnostics never contain source values or resolver exception text. Structural validity is separate from source-specific semantics and from acceptance. Activation remains not-authorized-by-artifact; goldAdmission remains not-admitted. New operations/purpose flags cannot appear in a sidecar to grant themselves access.

Resolver methods are trusted reviewed application interfaces over already selected evidence, not untrusted dynamic providers. `evidence(pin)` supplies selected bytes; every use checks the exact SHA and bound. `page` supplies qualified native page text. `grant` returns a typed Grant containing an actual SourceContract plus explicitly reviewed purposes. The callback requires the existing retain/parse/transform operation set, no holds, exact source/release and the exact input-contract fingerprint. Normalization and translation remain separate purposes of transform. A source JSON object, public URL, rights-file hash or invented pin cannot construct a Grant. All resolver witnesses must be included in the eventual reviewed factory's independently pinned input/context inventory. This candidate does not install that real-input factory.

## Exact record and native-location checks (F2)

The selected parsed file path/SHA/bytes and JSON or JSONL format/line/pointer/record ID are policy-bound. JSONL is split on literal LF bytes, not Unicode separators. Strict JSON rejects duplicate keys/nonfinite values. JSON Pointer decoding rejects invalid tilde escapes, append indices, leading-zero array indices and unresolved paths. Parsed source/release/record/original hash must match the selected input and actual native citation. Unknown upstream values are not replaced with guessed releases.

Targets resolve to their exact native extraction nodes. Whole-node evidence uses that node's inherited location. A narrower string field requires a separate qualified subfield locator with its own pin, exact record/pointer and native location; it cannot silently inherit a whole-line location as word evidence. Page/hash/span/range/line and UTF8 boundaries are checked against the existing native text. English output is never an offset source. Original native text and unknowns remain unchanged.

Assertion IDs are unique across assertion sections; conflict IDs have a separate unique namespace. Ambiguity, variant, competing assertion and external record references must resolve. Resolved conflict decisions require an independently mapped, pinned decision bound to the exact native record/original and competing IDs, not an arbitrary file. No original/superseded claim is removed.

Quantity witnesses are reviewed resolver mappings, not a new conversion engine. Their exact pin binds native record/original/target, source qualifier, normalized value/unit/basis, comparison/bound, conversion kind and factor/basis pins. Changing a factor, qualifier, unit or target invalidates the mapping. Literal-zero claims additionally agree with the native value lexeme and normalized zero. Unknown quantities stay unresolved; no trace/ND/blank-to-zero inference. Actual conversion definitions, density/food form, yields, nutrient retention, serving and wet/dry/edible bases remain source-policy responsibilities. This callback supplies no guessed values or factors.

## Qualified identity-role and source mappings (F1)

Opaque IDs are preserved as lexical source claim IDs; they are never cast to graph IRIs. `claim` returns a ResolvedClaim containing its own SourceContract, existing qualification result, exact candidate artifact and record locator. The callback verifies the result fingerprint, contract fingerprint/source/release/scope/candidate hash, exact source record ID/provenance, role and independently resolved graph IRI. Fixture qualification cannot satisfy a nonfixture caller. External product claims deliberately use their own qualified source/release; recipe provenance is not inherited.

The bounded product role is source-product-assignment, a resolver role label, NOT a new canonical graph class. It resolves to existing FoodProduct plus a source-scoped formulation/item snapshot represented by SourceRecord, Package and Market as applicable, and explicit bounded effective-period evidence. Package/market N/A requires reviewed evidence and a null resource; unknown is held. This slice supports explicit ISO-date closed validity intervals only; missing/open/unsupported temporal semantics stay unresolved for a separately reviewed mapping. Ingredient role resolves to qualified identity plus explicit material state, part and preparation. Missing form/snapshot/package/market/time or wrong role cannot support reviewed inheritance. No formulation/trade-item canonical type is invented.

`productIngredientLinks` remains a source assertion on that exact qualified assignment/snapshot. It does not establish culinary usability, equivalence, allergens or dietary suitability. A parent FoodProduct alone cannot establish formulation-specific composition or nutrient/dietary inheritance.

## Usability, variants and graph mapping

A supported usableAs assertion needs a reviewed use binding pinned to this exact native input, product/ingredient claims, formulation snapshot, package, market, effective date, food form, conditions and recipe reference. Null recipe reference is supported only through an independently qualified alternative use-scope record. Generic strings or arbitrary evidence files are insufficient. Existing unresolved/unsupported assertions remain unpromoted. A registered usability predicate must be explicitly supplied by the reviewed consumer mapping; the current application has no default binding. This candidate registers none. A synthetic-only example.invalid binding tests the gate, not a vocabulary installation.

Future common-graph mapping reuses the reviewed existing containers, with no added fields on closed source or graph records:

| Sidecar evidence | Existing boundary |
| --- | --- |
| Source/release/record/original hash | Citation sourceId/originalRecordId/revisionId/contentSha256; parsed artifact hash stays separate derivation evidence |
| Native anchors | Citation/assertion sourcePath with line/record/field and existing location hashes/ranges |
| Translation | TranslationRevision/translationOf with native input hash and separate English/review evidence; not ingredient identity |
| Quantity | Existing typed quantity/value assertion and derivation/unit/basis references after source-specific qualification |
| Exact/broader/narrower | candidateMatch while proposed; exactMatch/broaderMatch/reversed broaderMatch only with reviewed direction/domain/form mappings |
| Ingredient declaration/reference | ingredientOf/mentionsIngredient only under explicit domain/range/direction bindings; no generic contains/usability inference |
| Product formulation/item | SourceRecord snapshot plus existing FoodProduct/Package/Market; no new canonical type |
| UsableAs | Linked/unpromoted until explicit narrowly reviewed registered property and consumer context exist; never overload exactMatch, ingredientOf or preparedFrom |
| Conflict | Existing conflicting/superseded, contradicts/supersedes and decision/citation/derivation evidence, without destructive merge |

No graph output or mapping registry is installed here. Different regional forms, recipe components, ingredient alternatives and English names are not merged. Language/cultural attribution never establishes national territorial applicability. Dietary/allergen assessment, English translation quality, food identity, source-use rights, common/consumer admission and publication remain separate.

## Synthetic verification and remaining dependencies

Tests supply only invented parsed/native UTF8 text, source contracts, external qualified claims and resolver witnesses. External claims are qualified through the existing offline `qualify`; the callback is also exercised through that same boundary on a sourceAssertion wrapper. No `accept` is called and no real-data result is implied. Tests include source/release/record/artifact substitution, strict pointers and JSONL selection, native spans/UTF8/word locators, duplicate/cross references, permission invention/holds, zero/conversion/qualifier mismatch, role/formulation/package/market/time misuse, unregistered or unscoped usability, fixture scope and fixed diagnostics.

A real caller still needs exact permitted input/purpose grants, independently qualified native extraction/current-cache provenance, a pinned production resolver/identity mapping and actual consumer vocabulary/use semantics. Unknown claims remain held. Fresh independent56 review precedes any00 integration; source-restricted processing, translation/model runs, acceptance installation, public serving/runtime/production/CIX remain outside this candidate. Routine synthetic/correctness preparation requires no blanket reapproval. Full selected retained-set accounting remains separate from a usable-English consumer subset and from all-world completeness.
