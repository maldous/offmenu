## Runtime protection

`save-private-media-original.py` shares the existing writer lease, current claim scans, private directories, exclusive intents, physical reservations, protected floor, immutable original/provenance writes and failure retention primitives. It uses correct `.csv`, `.json`, or `.docx` suffixes. A prior successful original is rehashed and structurally checked without another GET. Its original acquired time does not change. Failed or uncertain intents and any partial block a fresh request indefinitely; a 30-day dedup period never becomes permission to retry.

The closed source pin binds URL, exact query pairs, method/body, media, rights evidence, source-specific conditions, limits, source-stage permissions and downstream holds. Mutable revisions are not relabelled as historical versions. WFP provenance includes author/distributor credit, exact source URL, actual acquisition time and body digest. ETag and Last-Modified are recorded as bounded SHA-256 observations in private provenance; their raw values are not exported or persisted. This intentionally preserves validator identity without retaining potentially capability-bearing header text.

New-media transport does not read proxy settings, forward credentials/cookies/referers, retry, range, issue HEAD, or discover endpoints. A streamed 64 KiB header envelope is shared by both responses for each PLOS source; overlong headers fail before source-body consumption. PLOS requires the exact stable publisher endpoint to issue one fresh 302 to the observed HTTPS storage host and object path. Only the six reviewed signed-query keys are accepted, with duplicate/extra keys, expired capabilities, other targets and another storage redirect rejected. Redirect bodies are never read. Capability values exist only in the volatile request object and are absent from report/error/claim/provenance output. The scheduler reserves both the publisher and storage host slots, preserving host caps and gaps across redirected sources.

CSV integrity checks UTF-8 BOM-aware decoding, the exact known prices header, bounded fields/rows and rectangular records. JSON checks duplicate/nonfinite values, depth, success, and the exact WFP dataset UUID. DOCX checks finite member/expanded/ratio bounds, all ZIP CRCs, duplicate/traversal/encrypted/unsafe members, required OOXML members and safe XML structure. It executes no scripts or external relationships and produces no extracted PLOS payload.

`collect-fixed-global.py` integrates source-specific request limits, host sets, filenames, media saving and metadata-only joins. Optional join summaries use exact member state groups and are recomputed by the closed sanitizer. Requests and byte totals count actual source operations only. Complete projection of all 4,753 assets and joins remains under the existing 96 KiB summary envelope in tests.

## Merge-compatible retained-input seam

The newly identified retained inventory is a distinct scope beyond these 81 units. `retained_contract_extension.py` supports source-bound rows with exact base/asset pins, unchanged original path/hash/extent, explicit permissions, effective nested read holds, evidence and nullable preparation/verification contracts. Both selection APIs default to no selected IDs. No family, file extension, digest match or suggested row becomes an implicit read grant. Current explicitly held assets, effective read holds and `.part`/`.partial` inputs cannot be selected.

`retained_integrity_verification.py` provides a separate review-only streaming verification primitive for exact approved retained identities. It reads at most the exact byte extent in 1 MiB chunks, retains at most 64 KiB for media observation, checks the absolute deadline between reads, verifies stable file identity and SHA-256, and emits closed metadata only. It does not copy, decompress, extract, write payloads, or mark next-stage readiness. A 13,132,516,914-byte identity can be proposed with a finite 1,200-second cap without changing the existing parser's 1 GiB original cap. The 95 GB OSM `.part` remains unselected. Prefix observations are not full archive/media validation. Actual large-file orchestration must use the existing bounded worker/termination envelope; the standalone function uses cooperative checks between local reads.

The 22-join and retained-input overlays must each be validated against the frozen baseline before composition. Pure join functions accept an explicit binding_manifest for that reviewed assembly and allow only the added member preparationContract to differ; source identities, holds, bindings and all other member metadata must remain equal. This optional baseline does not authorize a preparation or perform a read.

No concrete 998-row extension is activated by these generic functions. The reviewed contract owner supplies that separate selection and its exact resolved/held/unknown counts. Historical equal bytes never merge source releases, claims, country bindings or permissions.
